# Branching and release model

- **main** is always releasable. CI (`.github/workflows/ci.yml`: the frontend build, the engine compile and `formdeck_engine.py --selfcheck`) must pass before anything lands. No force-push to main.
- **Work branches** are short-lived and named by intent: `feat/<scope>` for new capability, `fix/<scope>` for repairs, and `docs/<scope>` or `chore/<scope>` when nothing ships to users. Scopes match the code: `editor`, `render`, `present`, `pdf`, `engine`, `mcp`, `intake`, `compiler`, `templates`, `pptx`, `desktop`, `docs`. Rebase on main before merging.
- **Commits** follow Conventional Commits with the version in the summary, `type(scope): summary (x.y.z)`, and a body that says what changed and why, for example `fix(render): keep autofit when a placeholder is resized (0.2.2)`. Types: `feat`, `fix`, `perf`, `refactor`, `docs`, `chore`, `build`, `ci`. The commit identity is `nodemode-ai <mackin@nodemode.ai>`.
- **The version bump is the last commit of every series**, `chore(release): 0.2.2 (0.2.2)`, and it changes every version in one go: `frontend/package.json`, `frontend/src/version.ts`, `backend/app/__init__.py`, `src-tauri/Cargo.toml`, `src-tauri/tauri.conf.json` and the version line in `README.md`. Nothing lands after it in the same series.
- **Compile branches** are `compile_v` plus the version with dots: `compile_v0.27.2`. Cut one from the version bump commit on main, never from a work branch.
- **Releases.** formdeck builds nothing in this repository. Pushing a `compile_vX.Y.Z` branch runs CI on it, and formcompiler (`nodemode-ai/formcompiler`) picks it up on its next 8-hourly watch run, or at once when its watch is run by hand. It builds macOS, Windows and Linux bundles (.app and .dmg, .msi and .exe, .deb and .AppImage, and the Flatpak) with the frozen engine sidecar, writes `latest.json` for the updater when the signing key is set, and opens a draft release `formdeck-vX.Y.Z` on its own release page. Review the draft and its notes, then publish it there. Compile branches are kept as the record of what was built.
- **Release flow, end to end:** merge the work branches into main, run `./formdeck doctor` and a throttled pass through the changed UI, commit the version bump, push `compile_vX.Y.Z` from it, wait for formcompiler, publish the draft on formcompiler.
- **Wiki.** Edit pages in `.docs/wiki/`, never in the GitHub wiki UI. `.github/workflows/wiki.yml` publishes the folder when it changes on main. The wiki must have one page created by hand once before the first publish.
